# Coverage Policy

`forwardmeasure-jpa-coverage` is the final reactor module and the sole
authoritative source of repository-wide production coverage. Module-local
JaCoCo reports remain useful while developing, but they cannot account for
code exercised from another module. For example, the shared adapter contract
tests execute Identity code even though those tests do not live in
`forwardmeasure-jpa-identity`.

## Production Scope

The aggregate report includes classes and execution data from:

- `forwardmeasure-jpa-core`;
- `forwardmeasure-jpa-identity`;
- `forwardmeasure-jpa-async-task`;
- `forwardmeasure-jpa-locking`;
- `forwardmeasure-jpa-tenancy`;
- `forwardmeasure-jpa-liquibase`;
- `forwardmeasure-jpa-quarkus`;
- `forwardmeasure-jpa-spring`; and
- `forwardmeasure-jpa-micronaut`.

`forwardmeasure-jpa-contract-tests` contributes its JaCoCo execution data but
not its test-support classes. The BOM, parent POM, and coverage module contain
no production Java classes and do not affect the result.

## Quality Gates

Every `mvn verify` enforces the following aggregate limits:

| Metric | Required value |
| --- | ---: |
| Line coverage | At least 85% |
| Branch coverage | At least 75% |
| Completely missed production classes | 0 |

The missed-class gate prevents a strong aggregate percentage from hiding an
entirely untested class. The line and branch thresholds are centralized in the
parent POM as `jacoco.minimum.line.coverage`,
`jacoco.minimum.branch.coverage`, and `jacoco.maximum.missed.classes`.

The limits may be raised as the suite improves. They must not be lowered to
make a failing change pass.

## Exclusions

Only compiler-generated bytecode is excluded:

- Hibernate canonical metamodel classes ending in `_`; and
- Micronaut bean-definition and introspection classes beginning with `$`.

`lombok.config` instructs Lombok to mark generated methods with
`@lombok.Generated`, which JaCoCo filters automatically. Entities,
repositories, services, converters, framework adapters, configuration code,
and error paths remain in scope.

## Reports

The aggregate goal generates all three standard formats under
`forwardmeasure-jpa-coverage/target/site/jacoco-aggregate`:

- `index.html` for local inspection and CI artifacts;
- `jacoco.xml` for SonarQube, Codecov, or another coverage service; and
- `jacoco.csv` for automated analysis.

The coverage module also merges all reactor execution data into
`forwardmeasure-jpa-coverage/target/jacoco-aggregate.exec` and applies the
same aggregate data to the Maven quality gate.

Run the complete gate with:

```bash
mvn clean verify
```

Do not run the coverage module in isolation against stale execution data when
making a release decision. The release result is the aggregate report produced
by the same clean reactor execution.
